Cold, per-call

Generic filesystem MCP

A raw read-file/grep-over-MCP tool still opens whole files fresh on every call — same token cost as an agent doing it manually, just wrapped in a protocol.

Warm, in-memory

Kenning's MCP

The daemon holds the graph in memory across calls, so ask/explore/recall answer from a live index — no cold start, no re-reading, the same warm graph the CLI and desktop app use.

  • Agent governance — instructions_*/tools_*/skills_* sync one shared catalog to every agent, instead of per-developer config.
  • No black-box answers — trace_submit rejects any claim that doesn't independently grep-verify against the real file.

Docs

Every command, one binary.

Every command accepts --hub <path> to target a hub other than the one auto-resolved from your current directory; most also accept --json for machine-readable output.

Setup & account
Command What it's for
kenning login [provider] Optional sign-in (GitHub or Google) — unlocks Cloud tier and keeps your tokens-saved history across reinstalls. Free tier works without it.
kenning logout Clears the signed-in identity everywhere — CLI and desktop app together.
kenning init [--force] Scaffolds a multi-repo hub: config, local state, and clones any repos declared in it.
kenning repo add <path-or-git-url> [--name] Register another repo into a hub, cloning it first if you passed a URL.
kenning repo delete <name> Remove a repo's checkout from disk and untrack it from the hub.
kenning up [--fresh-wiki] Indexes every repo in the hub and starts the background daemon.
Search & retrieval
Command What it's for
kenning search <query> [--repo] [--limit] Find a symbol or string literal by name across the whole hub.
kenning explore <symbol> [--repo] [--max-files] See a symbol's neighborhood: callers, callees, blast radius.
kenning ask <query> [--repo] [--limit] One call that runs both recall (docs/memory) and search_code (code).
kenning recall <query> [--repo] [--limit] Full-text search over your docs, memories, and verified traces.
kenning status Per-repo index health, plus a running tokens-saved count.
Keeping the index current
Command What it's for
kenning sync [--repo] Force an incremental re-index — the daemon already does this automatically on save.
kenning sync --repo <name> --reset Wipe and rebuild one repo's graph from scratch.
Knowledge: memory, traces & wiki
Command What it's for
kenning memory-store "<content>" --type --tags Save a typed, tagged memory — a decision, a bug's root cause, a convention.
kenning memory ingest [--repo] Bulk-load memory.md files into the searchable store (rows + FTS + embeddings).
kenning memory check [--repo] Report-only: memories with no backing file, or file sections not yet ingested.
kenning trace-submit <trace.json> Submit a structured trace of how something was verified — fail-closed.
kenning wiki bootstrap <repo> Generate the initial wiki page skeleton for a repo, from its index.
kenning wiki get <repo> [--slug] Fetch a wiki page, generating a skeleton first if it doesn't exist yet.
Advanced & manual control
Command What it's for
kenning index [--repo] [--jobs] The raw indexing step alone, without registering the hub or a daemon.
kenning serve --port 8082 The same daemon `up` starts, run in the foreground for debugging.
kenning audit [--strict] [--quiet] Hub hygiene lint — naming, dangling links, staleness. Built as a CI gate.
kenning migrate [--knowledge] [--yes] One-time import from mcp-memory-service or existing knowledge/ docs.
MCP — Claude Code or any MCP client
$ claude mcp add kenning -- kenning mcp
Transport What it's for
kenning mcp (stdio) One process per agent connection — 20 tools, including memory_store, trace_submit, and wiki_get.
Daemon /mcp (HTTP) One always-on endpoint shared across multiple agent connections — 17 tools, warm index already in memory.
